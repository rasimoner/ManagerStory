## Delivery rules

Keep one MatchEngine and one shared 2D/3D presentation clock. Preserve approved goalkeeper distribution, goal/set-piece behavior and match transitions. Retain current half-speed label mapping; do not apply it again. Engine decision changes may change historical outcomes, but repeated identical inputs must remain deterministic. Keep presentation fixes separate from engine decision changes.

Use short targeted checks, at most two meaningful candidate attempts per issue, and Safari user testing for visual approval. Avoid browser installation loops, new video production and repeated broad test runs. Update the existing private iPhone preview for future deliveries; do not change main or the public release without a release instruction.

## New 3D view in the game (2026-10-15)

The user reviewed a standalone prototype (`proto/yeni-gorunum`, `prototypes/new-view/`) on iPhone, confirmed it "feels like a match", asked to fix out-of-play behaviour and to put this view into use.

What changed in the product (`dist/`):

- `match3d-newview.js` is now the default 3D renderer (`?eski3d=1` loads the previous `match3d-career.js` for comparison). It mounts into the same `#career-3d-host`, keeps the radar and the approved goal overlay, and falls back to 2D on WebGL failure.
- `newview/` holds the view: stylized footballer mesh on a Mixamo skeleton (`footballer.js`), recorded idle/walk/run clips with hand-keyed football actions (`actions.js`), ball/player runtime (`runtime.js`), engine-event director (`director.js`) and the toon stadium with animated crowd (`stadium.js`). Model data: see the open-assets update below.
- One engine, one clock: `match3d-live-clock.js` got two hooks. The existing presentation clock follows the new view (`ManagerStoryNewView.gate`) and the next engine minute is generated only after the view has played the current one (`ManagerStoryNewView.busy`). A shot is held back in the clock until the view has played its outcome, so score/goal overlay never spoil it. Pause, speed (0.5/1/2), half time, injuries/substitutions and the single finish run through the existing paths unchanged.
- Out of play: while the engine says the ball is in play it stays inside the lines; on `ballOut` it crosses at the engine's out point and play stops until the restart. Throw-ins (ball held at the chest behind the line), corners (ball on the corner spot) and goal kicks are taken from the engine restart spot.

Checks:

- Out-of-play check over 5 engine matches (fixtures 2, 3, 5, 11, 19): 0 frames with the ball out while the engine says in play (was 5 episodes / 537 frames in fixture 3 before the fix).
- Browser run of a full career match (fixture 3, headless Chromium, test speed knob `?nvtest=10`): 473 events, same result as the engine alone (2–2), half time and finish reached, 0 console errors, 0 director stalls. Score in the header never ran ahead of the view.
- Gate check: 19 engine minutes generated during play, none while the view was still behind.
- 2D↔3D switch, other tabs, pause/resume and page reload mid-match: no errors; the view resumes from the current moment.
- Targeted Node tests (managerstory, live-clock, career, adapter, matchengine phases 1–3): 129/133; the same 4 tests fail on the unchanged baseline (historical test debt).
- Visual approval: pending, user tests in Safari.

Open for this view: pass/shot/keeper actions are hand-keyed (no mocap yet); no headers or slide tackles; engine events arrive per minute and sometimes out of order, so players can shift together at minute boundaries; some engine `block` events are keeper saves.

## Open assets and fullscreen view (2026-10-15)

User decisions: everything must be free and open source (no paid or licensed assets); the 3D view needs a fullscreen/minimise button with the broadcast-style controls of the reviewed real-match preview.

- Mixamo removed. The view now builds ManagerStory's own skeleton (`dist/newview/rig.js`) and plays idle/walk/jog/sprint clips retargeted from Quaternius' CC0 Universal Animation Library by `tools/build-rig.mjs` into `dist/assets/models/footballer-rig.json` (112 KB, replaces the 3.9 MB Xbot file). GLTFLoader, SkeletonUtils and BufferGeometryUtils are no longer shipped. Licences: `docs/open-assets.md`.
- Locomotion blends walk → jog → sprint; the CC0 jog is long-striding, so its stride is shortened up to 30% at football speeds.
- Fullscreen: a button on the 3D view (⤢/⤡). The view covers the screen (iPhone Safari has no element fullscreen; the Fullscreen API is used where available) with a score bug and clock, the live commentary line, the ball carrier, radar, camera choice (Otomatik/Yayın/Yakın/Tribün), speed (0.5/1/2×), pause/resume and Müdahale (leaves fullscreen and opens the decision sheet). It stays across the app's re-renders and leaves by itself at half time, an injury stop and the end of the match. Portrait and landscape layouts.

Checks: browser full match (fixture 3) in fullscreen with the open rig — 473 events, 2–2 as the engine, fullscreen held in the first half and left at half time, 0 errors, 0 stalls; fullscreen controls (camera, speed, pause/resume, minimise, Müdahale) exercised with 0 errors; `tests/managerstory.test.cjs` 56/56 (includes the offline asset list). Visual approval pending in Safari.
